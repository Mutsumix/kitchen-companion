# 2026-07-20(深夜の部): ダウンロード遅延の解明とマルチスレッド化+フィラー

## ダウンロード遅延(20〜60秒)の玉ねぎ剥き

「応答が遅い」の原因は一枚岩ではなく、複数の要因が積み重なっていた:

| # | 原因 | 対策 | 効果 |
|---|---|---|---|
| 1 | TCP送信バッファ5.7KB(既定) | 64KBに拡大 | 上り 25→50KB/s |
| 2 | Wi-Fi省電力モード | esp_wifi_set_ps(NONE) | LAN RTT 186ms→7ms |
| 3 | 受信ループ内の毎チャンクI2Cタッチポーリング | 200ms間隔に間引き | 下り 7→31KB/s |
| 4 | lwIP受信メールボックス6個(既定) | 64個に拡大 | 体感20秒弱まで改善 |
| 5 | ビルドキャッシュに新旧sdkconfigが混在 | cargo clean -p esp-idf-sys | 設定が確実に反映 |

- 切り分けの決め手は「**Worker内部の計測とデバイス体感の差分**」と「**上りと下りの非対称性**」
- 別モデルへの解析依頼用に `debug-logs/analysis-facts.md`(事実+棄却済み仮説+質問)を作成する手法を導入

## 通信の別スレッド化(構造の本丸)

- 通信専用スレッド(TLS接続を所有、スタック26KB明示)+ mpscチャネル+AtomicBoolキャンセル
- メインループは送受信中も止まらなくなり:
  - **フィラー音声**(「ちょっと考えるね」等、キャラの声で事前TTS→本体埋め込み)が待ち時間に流せる
  - 考え中の顔アニメーションが動く
  - どのタイミングでもバージイン可能(考え中は通信キャンセル、再生中は再生中断)
- 遅延到着した応答は awaiting フラグで読み捨て(割り込み後の混線防止)

## フィラー音声の仕組み

- `tools/make_fillers.py`: Workerの試聴エンドポイント(/voice)からキャラごとの声で生成
  → 16kHzモノラルraw化 → `assets/fillers/` → include_bytes!で本体埋め込み(SDカード不要)
- 起動時にステレオ化+減衰(-6dB)+末尾無音を付与、2種をローテーション再生
